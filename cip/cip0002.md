## Summary

Tentative follow-on to CIP-0001. Redesign how [`aistats/jekyll-theme`](https://github.com/aistats/jekyll-theme) selects conference branding so yearly stubs do not need a magic `style: aistats` key (or so that key is replaced by a clearer, documented contract). Until this CIP is accepted and implemented, stubs must keep `style: aistats`.

## Motivation

The shared theme multiplexes several brands (`aistats`, `pmlr`, `gpss`, …) through `site.style`. That value drives CSS, favicons, style-specific includes (`_includes/layout.html` → `aistats/home.html`), past-meeting repo filtering, and some meta tags. It works, but it is opaque to new organisers and couples every conference stub to theme internals. A theme revamp should make branding explicit and safer to omit or default for AISTATS-only sites.

## Detailed Description

Scope lives primarily in **jekyll-theme**, with a small stub/`_config.yml` follow-up once the theme contract is stable.

Likely directions (to be decided when this CIP is accepted):

1. **Default AISTATS** when `style` is unset on AISTATS organisation sites, with an explicit opt-in for other brands.
2. **Rename / document** the key (e.g. `brand:` or `theme_variant:`) and update all consumers.
3. **Split themes** so AISTATS conference sites use a dedicated remote theme and no longer share include namespaces with PMLR/GPSS.

Out of scope for the tentative note: visual redesign of the society site, or changing `remote_theme: aistats/jekyll-theme` without a migration plan for live `aistats20XX` repos.

## Implementation Plan

1. Audit all `site.style` uses in jekyll-theme.
2. Propose the new branding contract and migration for existing AISTATS years.
3. Implement theme changes; release/tag.
4. Update stub `_config.yml` (and society site if needed); document in stub README/`_doc`.

## Backward Compatibility

Live conference sites that set `style: aistats` must keep working through any transition (support old key, or provide a one-line config bump with clear release notes).

## Testing Strategy

- Build stub and at least one recent year site against the revised theme.
- Confirm CSS, favicon, home include, and past-meetings listing still resolve.
